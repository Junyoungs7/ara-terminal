## 왜 안 잡혔나 — 게이트가 볼 수 없는 부류다

재접속 버그를 다시 보면 이렇다:

```
사이드바에서 더블클릭  →  connectProfile  →  실패하면 되묻는다(호스트키·비밀번호)
끊긴 뒤 [다시 접속]    →  sshRestore      →  connect() 맨손. 되묻는 길이 **통째로 없다**
```

**둘은 같은 일을 한다. 그런데 한쪽만 온전했다.**

이건 `typecheck` 가 못 본다(둘 다 타입이 맞다). `vitest` 도 못 본다(각자는 자기 일을 한다).
`scan:*` 도 못 본다(문법이 아니다). **"둘이 같은 일인데 다르다"는 것을 아는 게이트가 없다.**

---

## 🔴 이 패턴은 이번 세션에서만 **다섯 번** 나왔다

| 판 | 온전한 쪽 | 빈약한 쪽 | 증상 |
|---|---|---|---|
| 1.0.8 | SSH 접속이 `selectSession` 을 부른다 | 로컬 AI·작업 프로필·[여기서 터미널 열기]×2·MCP 세션 | 탭만 바뀌고 **화면은 옛 세션** |
| 1.0.9 | 아라 채팅에 파일 드롭 | 터미널에 드롭 — **아무 일도 안 남** | 파일을 못 건넴 |
| 1.0.9 | `pastePaths()` 가 이미 있었다 | 내가 **똑같은 것을 새로 만들 뻔** | 두 벌이 되면 한쪽만 낡는다 |
| 1.0.11 | `connectProfile` 이 되묻는다 | `sshRestore` 는 안 묻는다 | **재접속이 영영 실패** |
| 1.0.11 | `connectProfile` 이 치수를 넘긴다 | `sshRestore` 는 안 넘긴다 | 복원된 세션의 **첫 줄이 접힘** |

**다섯 중 넷이 사용자 제보로 발견됐다.** 우리가 먼저 못 찾았다는 뜻이다.

⚠️ 그리고 **한쪽은 SSH, 한쪽은 로컬** 인 경우가 특히 많다 — SSH 쪽이 먼저 만들어지고 다듬어진 뒤
로컬 쪽이 나중에 붙으면서 손질이 덜 된 것으로 보인다. 그 가설을 점검에서 확인한다.

## 무엇을 찾나 — "같은 일을 하는 길이 둘인데 한쪽만 온전한가"

### 훑을 축 여섯

| # | 축 | 구체적으로 물을 것 |
|---|---|---|
| A | **접속·재접속** | 세션을 만드는 길 전수(사이드바·탭바 ＋·작업 프로필·MCP·복원·재접속·복제·AI CLI). 각각 ① 실패하면 되묻나 ② 치수를 넘기나 ③ 칸에 올리나 ④ 탭 이름·그룹을 같게 두나 |
| B | **로컬 vs 원격** | 같은 기능이 양쪽에 있는 자리(파일·업로드·로그·모니터·AI). 한쪽에만 있는 확인·안내·오류 처리 |
| C | **본창 vs 떼어낸 창** | 떼어낸 창에서 **안 되는 것**이 무엇인가. 되어야 하는데 안 되는 것과, 일부러 막은 것을 가른다 |
| D | **실패했을 때 말하나** | 실패를 `catch {}` 로 삼키거나 한 문장으로 뭉개는 자리. 재접속 버그의 *"잠시 후 다시 시도하세요"* 가 그 예 — **사유를 안 보여 주면 사용자가 풀 수 없다** |
| E | **되돌릴 수 없는 일에 확인을 받나** | 세션 종료·파일 삭제·컨테이너 제거·sudo. 한쪽 길에만 확인이 붙어 있지 않은가 |
| F | **중복 구현** | 같은 계산을 두 곳이 따로 하는 자리(인용·경로 조립·크기 계산·시각 포맷). 한쪽만 고쳐질 씨앗 |

### 산출물은 **표 하나**다

각 줄: `축 | 온전한 쪽(파일:줄) | 빈약한 쪽(파일:줄) | 무엇이 빠졌나 | 사용자에게 보이는 증상 | 크기`

⚠️ **"보이는 증상"을 못 적으면 그 줄은 버린다.** 증상을 못 쓰는 차이는 대개 **일부러 다른 것**이다
(예: 복원은 [파일] 탭으로 안 넘어간다 — 그건 결함이 아니라 결정이다).

## 어떻게 — 읽기 전용 3갈래 + 메인 검증

`docs/orca-analysis.md` 를 만든 방식과 같다. 서로 결과를 안 보는 독립 조사 셋:

| 갈래 | 범위 |
|---|---|
| **S1 접속·세션** | 축 A·C — 세션을 만들고 없애고 되살리는 모든 길 |
| **S2 기능 대칭** | 축 B·F — 로컬/원격 쌍, 중복 구현 |
| **S3 실패·확인** | 축 D·E — 오류를 삼키는 자리, 확인이 빠진 파괴적 동작 |

🔴 **규율**(지난 라운드에서 값을 증명한 것들):
- **고치지 마라.** 이 라운드는 **재는 일**이다. 제품 코드 수정 0
- **인용은 `파일:줄`.** 읽기로 낸 결론과 **재서 낸 결론을 구분해서** 적어라
- **0 건이 나오면 양성 대조**를 걸어 검색이 도는지부터 확인해라(부재와 "내 검사가 못 찾음"은 다르다)
- **창을 띄우지 마라** · `npm test` 전체 금지(포트 39217) · git commit 금지
- 추측으로 "빈약하다"고 적지 마라 — **온전한 쪽이 무엇을 하는지 먼저 적고** 그것이 없음을 보여라

## 그다음 — 게이트로 내릴 수 있는 것만 내린다

점검이 끝나면 **찾은 것 중 기계가 볼 수 있는 축**을 골라 스캐너로 만든다.
⚠️ **전부 게이트로 만들려 하지 않는다.** 1.0.8 에서 `scan:place` 를 만들었다가 **버렸다** —
리스너 하나로 고치자 지킬 "단일 헬퍼"가 없어졌기 때문이다. **성질 하나에 게이트 하나**,
그리고 **못 잡는 범위를 파일 머리에 적는다.**

지금 떠오르는 후보(점검 결과가 정하겠지만):
- `connect(` 를 `connectProfile` 밖에서 부르는 자리 — 재접속 버그의 모양
- `catch {}` 가 **빈 블록**인 자리(삼키는 것과 "여긴 무시해도 된다"를 주석으로 가른다)
