## 4. 이식 방식 규칙

### 4-1. 기능 단위 재작성
- 복사가 아니라 **기능 단위 재작성**입니다. Orca 는 기능 하나가 다섯 자리에 흩어져 있고 거의 모든 기능이 호스트 선택(로컬/WSL/SSH/원격)을 인자로 받습니다(`기능 E-1:931-933`). 1차는 호스트 축을 남겨 두되 로컬부터 채웁니다(M8 에서 원격).
- 한 항목 = 한 라운드. 라운드 시작 때 `D:\orca` 의 그 시점 HEAD 를 읽고, 항목 끝에 대응표 그 항목의 `orcaRef` 를 **읽은 커밋**으로 바꿉니다. `D:\orca` 는 월요일마다 앞으로 당겨지므로(1-1) `7a7f46f8a3` 에 묶어 두지 않습니다.
- Orca 의 시험(`*.test.ts` 동거)은 함께 옮깁니다. 옮긴 시험이 통과해야 `ported` 입니다.

### 4-2. 대응표 상태 값
| status | 뜻 | 누가 바꾸나 |
|---|---|---|
| `planned` | 아직 | — |
| `porting` | 라운드 진행 중 | 라운드 시작 |
| `ported` | 옮김, 시험 통과, `orcaRef` = 읽은 커밋 | 라운드 끝 |
| `needs-sync` | 월요일 점검에서 그 항목 경로가 "반영 필요"로 분류됨 | 월요일 점검 분류 |
- 2차를 시작할 때 2차 항목을 대응표에 더합니다(`기능:1166` 한계 3).

### 4-3. 월요일 점검과의 연결
- `scripts/ops/orca-watch.ps1` 는 재료만 모으고(`:1`), 보고서에 "분류 대기 | 반영 필요 | 새 후보 | 무관" 표를 만듭니다(`:208-209`).
- 분류는 Claude 세션이 합니다. **"반영 필요" → 그 항목 `needs-sync`**, **"새 후보" → 2·3차 후보로 orca-features 에 행 추가**, "무관" → 그대로.
- `needs-sync` 항목은 그 주에 진행 중인 마일스톤 끝에 한 라운드로 모아 반영합니다. 진행 중 마일스톤의 항목이면 그 라운드에서 바로 반영합니다.
- herdr 매니페스트 변경도 같은 표로 들어옵니다(PROGRESS `:10`). 매니페스트 파일 변경은 M3 이후 항상 "반영 필요"로 봅니다(상태 판정이 걸려 있음).

## 5. 성능 규칙

### 5-1. 예산 (기준선 측정 후 채움)
| 지표 | 기준선(M0, Electron 31) | 허용폭 | 게이트 |
|---|---|---|---|
| 켜는 시간 | `__ ms` | `__ %` | 마일스톤 끝 |
| 유휴 메모리(전 프로세스 합) | `__ MB` | `__ %` | 마일스톤 끝 |
| 유휴 CPU | `__ %` | `__ %p` | 마일스톤 끝 |
| 작업 공간 여는 시간 | `__ ms` | `__ %` | 마일스톤 끝 |
| (M3 부터) 에이전트 3개 유휴 메모리 | M3 에서 첫 측정 | `__ %` | M3 이후 마일스톤 끝 |
- 목표 수치는 두지 않습니다. "기준선보다 느려지지 않게"가 기준입니다(결정 `:48`). 허용폭은 5회 측정 흩어짐에서 정합니다.
- 같은 PC·같은 조건(dev 끔, 다른 앱 최소)에서만 비교합니다. 다른 PC 의 숫자와 비교하지 않습니다.
- **허용폭 규칙**(`tests/perf-baseline.cjs` 머리말과 같음): 흩어짐 = MAD(중앙값 절대편차), 3×MAD ≈ 2σ.
  - 켜는 시간·유휴 메모리·작업 공간: 허용폭 = max(바닥, 3×MAD/중앙값), 상한 = 기준선 × (1 + 허용폭). 바닥은 켜는 시간 10% · 메모리 5% · 작업 공간 10%.
  - 유휴 CPU: 0 근처라 %p 로 봅니다. 허용폭 = max(1.0%p, 3×MAD), 상한 = 기준선 + 허용폭.
  - 허용폭은 기준선을 잴 때 계산해 `docs/perf-baseline.json` 에 박습니다(게이트 판의 흩어짐으로 늘리지 않음). M0·M1 동안은 실패 시 1회 재측정(`--retries=1` 기본), M2 부터 `--retries=0`.
  - 기준선과 CPU·코어·RAM·OS 가 다르면 비교를 거부합니다(exit 2). 양성 대조: `ARA_PERF_INJECT_DELAY_MS=3000 npm run perf:gate` 는 실패해야 합니다(패키지본은 이 변수를 읽지 않음).

### 5-3. 프로세스 배치표

| 자리 | 무엇 |
|---|---|
| **main** | 창·메뉴·IPC 중계, 설정·작업 공간 저장, SSH 접속(ssh2, 터미널 공간), 터미널 공간 로컬 PTY(2차 M11 전까지), 에이전트 훅 수신(AI-04 — Orca 배치를 따름 [추측: Orca 는 `src/main/agent-hooks/` 로 main 에 둠]), 사용량 폴링(가벼운 HTTP), 자동 업데이트, MCP 서버 |
