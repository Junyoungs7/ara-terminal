## 2. 두 제품은 어디서 갈리나

**겹치는 것은 "터미널 + AI CLI" 한 층뿐이다.**

| | Orca | A.R.A |
|---|---|---|
| 정체 | 혼자서 에이전트 다섯을 병렬로 굴린다 | 사내 서버를 운영하며 AI 를 곁들인다 |
| 원격 모델 | 원격에 **분리 데몬** 배포 → 연결이 끊겨도 PTY 가 산다 | ssh 채널 직결 → tmux 없으면 같이 죽는다 |
| 저쪽만 | 워크트리 병렬 · 모바일 · `orca` CLI · Design Mode · GitHub/Linear · 스킬/플러그인 | — |

## 3. 가장 큰 수확 — B1 의 답은 "추론을 그만두는 것"

우리가 계획한 B1 은 *"두 신호(프롬프트 표 + 프로세스 트리)로 더 잘 추론하자"* 였다. **틀린 방향이었다.**

`src/shared/agent-status-types.ts:1-3`:
> *"상태는 훅에서 온다(Claude, Codex 등) — **터미널 제목에서 추론하지 않는다.**"*

Orca 는 로컬 HTTP 서버를 띄우고 각 CLI 의 훅 설정에 그 주소를 써 넣는다. 훅은 셸 한 줄이다:

```sh
printf '%s' "$payload" | curl -sS -X POST "http://127.0.0.1:${ORCA_AGENT_HOOK_PORT}/hook/claude"
```

판정은 이걸로 끝난다(`providers/codex-events.ts:110-127`):

| 훅 이벤트 | 상태 |
|---|---|
| `SessionStart` · `UserPromptSubmit` · `PreToolUse` · `PostToolUse` | **working** |
| `PermissionRequest` · 질문 도구의 `PreToolUse` | **waiting** |
| `Stop` | **done** |
| 그 외 | **`null` — 아무 주장도 안 함** |

**"침묵"이 이 함수의 입력이 아니다.** 3분 빌드는 `PreToolUse(Bash)` → working 을 찍고 조용할 뿐이라
대기로 읽힐 방법 자체가 없다. 우리 `aiSessions.ts:65` 의 `idle >= 60초` 가 답하려던 질문을
저쪽은 **아예 묻지 않는다.**

### 우리는 Orca 보다 싸게 할 수 있다

훅은 *실행 호스트의* `127.0.0.1` 로 POST 한다. 원격이면 거기 받는 사람이 있어야 하고 —
Orca 는 그래서 릴레이 데몬을 배포한다. **우리는 데몬이 필요 없다:**

1. `client.forwardIn('127.0.0.1', 0)` — **역방향 터널**(ssh2 가 이미 제공, 우리 `PortForward` 는
   `forwardOut` 만 쓰고 있다). 원격 포트를 하나 받는다
2. 원격 `~/.claude/settings.json` 에 훅을 심는다 — **SFTP 로**. 우리 `SftpService` 가 이미 하는 일이고,
   Orca 도 `ssh2` 의 `SFTPWrapper` 로 똑같이 한다(`agent-hooks/installer-utils-remote.ts`)
3. 터널로 들어오는 POST 를 받아 상태를 갱신한다

**원격에 아무것도 설치하지 않고 우리 PC 에 포트도 안 연다.** 이미 있는 두 조각의 조합이다.
저쪽이 데몬을 만든 건 *연결이 끊겨도 살아 있어야 해서*지 훅 때문이 아니다.

**한계는 정직하게 말한다** — 연결이 끊기면 훅도 못 온다. 그때 할 말은 "끝났다"가 아니라
`unverifiable` 이다(§4).

### 같이 가져올 값싼 것 셋

| | 무엇 | 크기 |
|---|---|---|
| a | **타임스탬프 둘.** `updatedAt`(모든 이벤트) / `stateStartedAt`(상태 변화만). 알림 ID 를 `agent:<pane>:<stateStartedAt>` 로 만들면 같은 상태의 반복 이벤트가 **OS 알림 한 개로 합쳐진다** — 중복 제거 표가 필요 없다 | ~3줄 |
| b | **`restoredUnconfirmed`.** 재시작 때 복원된 미완료 상태에 표시를 달고 **나이와 무관하게 "신선하지 않음"** 으로 취급. 화면엔 그리되 아무것도 안 믿고, 첫 실제 훅이 지운다. "재시작하니 유령 스피너가 부활"이 사라진다 | 불리언 1개 |
| c | **화면은 즉시, 알림은 1.5초 늦게.** 잠깐 `done` 을 찍고 이어 일하는 CLI 가 자기 알림을 스스로 취소하게 된다 | ~15줄 |

## 4. 정직한 상태 어휘 — 우리가 이미 도달했던 결론의 완성형

`docs/reference/ssh-execution-boundary.md`. 첫 줄이 *"이전엔 docs 에 이걸 적어 둔 데가 없었고,
에이전트도 사람도 오류 문자열에서 추측하다 틀렸다"* 다 — **우리 8080 로그 사고와 같은 사고를
겪고 규약으로 만든 것**이다.

어휘는 셋으로 고정, **동의어 금지**: `live` / `unverifiable` / `exited`.

> *"`exited` 는 그 프로세스를 소유한 호스트로부터의 **긍정적 부재 증거**를 요구한다.
> 전송 실패는 언제나 `unverifiable` 만 낳는다."*

`unverifiable` 과 `exited` 를 가르는 **순서 있는 네 시험**:

1. **그 신호를 낸 게 소유 호스트인가, 우리 장부인가?** — 클라이언트 집합에 없음·조회 예외·
   소켓 닫힘·타임아웃은 **구조적으로** `unverifiable` 이다. 필드 이름이 무엇이든.
2. **그 대상의 원격 PTY 가 한꺼번에 조용해졌나?** — 링크가 끊긴 것이지 동시에 죽은 게 아니다.
3. **종료 이벤트가 지금 그 신원과 맞나?** — 낡은 이벤트, 대체된 세대의 이벤트는 증거가 아니다.
4. **반환된 상태가 실제로 성공 주장인가?** — 실패라 보고했는데 성공했을 수 있다.
   **반환값 대신 바뀌었어야 할 영속 상태를 확인하라.**

> *"긍정적 호스트 증거에 못 미치면 전부 `unverifiable` 이다. 그걸 `exited` 로 보고하는 것이
> 이 문서가 막으려는 오류다 — **살아 있는 작업을 고아로 만들고, 같은 워크트리 위에 중복 실행을
> 냉시동시킨다.**"*

⚠️ **저쪽도 이걸 코드로 강제하지는 못한다.** 린트도 래칫도 없고 타입 모양(`{status:'unverifiable';
reason: string}` — reason 이 필수)과 리뷰로 버틴다. 새 표면이 맨 불리언을 돌려주면 안 잡힌다.

**우리 적용점**: `aiSessions.ts` 의 3상태(`busy`/`quiet`/`gone`)에 "모른다"가 없다.
`gone` 은 지금 우리 장부(세션 목록에 없음)로 판정하는데, 위 시험 ①에 따르면 그건 `unverifiable` 이다.

## 6. 인가 모델 — **가져오면 안 된다. 우리 것이 더 강하다**

우리 MCP 불변식: *AI 는 명령 문자열을 못 보낸다 — 고정 카탈로그의 `{id, args}` 만.*

**Orca 에는 그 경계가 CLI 에 없다.** 명령 목록은 고정(~200개)이지만 그중 셋이 자유 문자열을 받는다:

- `orca terminal create --command "<문자열>"` → PTY 에서 실행. 스키마가 `z.string()` + 길이 제한뿐
- `orca eval --expression "<JS>"` → 내장 브라우저에서 실행
- `orca computer click/type-text` → **다른 데스크톱 앱**을 접근성 API 로 조종

경계는 명령이 아니라 **전송로**에 있다 — 유닉스 소켓 `0600` + 파일에 적힌 베어러 토큰
(`randomBytes(24)`, 비교는 `!==` 로 상수 시간 아님). **같은 OS 사용자로 도는 아무 프로세스나
그 토큰을 읽어 앱을 완전히 조종할 수 있다.** 호출자 신원도 능력 범위도 동의 창도 없다.

그리고 `src/main/agent-trust-presets.ts` 는 CLI 의 **"이 폴더를 신뢰합니까?" 창이 뜨지 않도록
신뢰 표식을 미리 써 넣는다.** 자기 주석이 *"사용자가 수락한 뒤 에이전트가 쓰는 바로 그 신뢰
산출물을 미리 써 두는 것이 **유일한 문서화된 우회**"* 라고 적는다.

일관된 입장이긴 하다(에이전트가 이미 내 권한으로 셸을 쥐고 있다). **그러나 우리 입장과 다르고,
우리 것을 약화할 이유를 하나도 못 찾았다.** 오히려 `agent-trust-presets.ts` 가 우리 불변식이
왜 있는지 보여 주는 사례다.

### 다만 저쪽 경계에서 훔칠 것 하나 — 플래그 밀수

`src/relay/git-exec-validator.ts:37-40`:
> *"읽기 전용 플래그가 있는지 확인하는 것으로는 부족하다 — 요청이 `--list`(검사 통과)와
> `--add`(쓰기 수행)를 **함께** 담을 수 있다. 쓰기 연산을 명시적으로 거부하라."*

허용목록만으로는 못 막는다. 우리 카탈로그가 사용자 플래그를 통과시키는 자리가 있으면 같은 구멍이다.

또 하나: **`orca agent-context --json` 이 살아 있는 명령 표를 스스로 직렬화한다** —
*"에이전트가 발견하는 것이 실제 명령 표에서 어긋날 수 없게."* 우리 MCP 카탈로그도 같은 방식으로
자기를 뱉게 하면 문서 드리프트가 영구히 사라진다.

## 7. 터미널·SSH — 우리가 확인한 것과 고칠 것

### ✅ 우리가 이미 맞게 한 것 (확인 완료)

- **`hostVerifier` 가 동기 함수다**(`SshBackend.ts:62`). 저쪽 문서가 가장 크게 경고하는 함정 —
  *"`async` 로 만들면 ssh2 가 Promise 를 받고 `!== undefined` 라 **즉시 키를 수락**한 뒤 콜백 결정을
  무시한다. TOFU 가 조용히 꺼진다."* 우리는 해당 없음.
- **알고리즘 다운그레이드 벡터도 해당 없음.** 우리 `verifyHostKey` 는 **호스트 ID 로만** 조회하고
  지문이 다르면 무조건 `mismatch` 다. 저쪽은 알고리즘별로 저장해서 "다른 알고리즘 = 첫 접속"
  구멍이 있었고 그래서 `algorithms.serverHostKey` 재정렬이 필요했다. 우리 설계엔 그 구멍이 없다
  (대신 호스트가 키를 정당히 교체하면 "변경!"으로 뜨는 오탐 방향 — 안전한 쪽이다).
- **pty→렌더러 전송로는 우리가 낫다.** 우리는 `postMessage` 단일 복사, 저쪽은 `webContents.send`
  로 매 배치마다 구조화 복제한다(`src/main/ipc/pty/`·`src/preload/` 어디에도 MessagePort 없음).
- **백프레셔도 우리가 옳은 쪽에 있다.** 저쪽이 겪은 버그(`terminal-pty-ack-gate.ts:87-94`)는
  "받은 바이트"로 ACK 해서 렌더러 큐가 무한히 자란 것인데, 우리는 `xterm.write` 콜백을 세므로
  **파싱 기준**이다.

### 🔧 우리가 고칠 것

| | 무엇 | 근거 |
|---|---|---|
| 1 | **누적 ACK 로 바꾼다.** 델타 카운터는 메시지 하나만 유실돼도 창이 영구히 좁아진다. 누적 총계는 다음 ack 에서 스스로 낫는다 — *"TCP 식 누적 ACK 라 유실된 ACK 가 영구 부채가 되지 않는다"* | 2줄. "터미널이 한참 쓰면 느려진다" 부류를 없앤다 |
| 2 | **일시정지에 자동 해제 실패안전.** *"pause 는 fire-and-forget 이라 resume 이 유실될 수 있다(메인 크래시, 소켓 드롭) — 유실된 resume 이 셸을 영영 멈추게 하면 안 된다"* → 5초 자동 재개, 여전히 넘치면 다시 멈춘다 | 우리도 같은 모양이다 |
| 3 | **`.cmd` 인자 인코딩** — `ClaudeCliEngine.ts:68` 이 유일한 `shell: true` 다. Windows 에서 `claude` 는 npm shim(`.cmd`)일 수 있고, `CommandLineToArgvW` 와 `cmd.exe` 가 **같은 명령줄을 다르게 읽는다.** 저쪽 실측: `["a b", 'c"d', "e%F%g", "h&i", "j^k"]` → `["a b", 'c"d', "e^%F^%g", "h"]` — *"`&` 가 인자를 자르고 나머지를 명령으로 실행했다"* | R1 이 `resumeId` 는 막았지만 **구조가 남아 있다.** 그 줄에 들어가는 다음 자유값이 곧 주입이다 |
| 4 | **"프로세스 목록이 비었다"를 죽음의 증거로 쓰지 않는다** — *"빈 표는 아무것도 안 돈다는 **주장**이고, 호출자는 그 주장에 따라 트리를 죽었다고 선언한다. '사용 불가'는 '비었음'과 구분돼야 한다 — 둘을 뭉갠 것이 PTY 트리가 자기 teardown 에서 살아남은 경위다"* | §4 의 같은 규율 |
| 5 | **프레임 붙인 히스토리 로그** — *"크래시는 마지막 append 를 찢을 수 있다. 길이 접두어가 있으면 찢긴 꼬리를 감지해서 이스케이프 시퀀스 절반을 재생하는 대신 마지막 완전 프레임에서 자른다."* seq 가 안 이어지면 **로그 전체를 거부**한다(구멍 난 채 재생하지 않는다). UTF-16 서로게이트 쌍 분할 가드도 | 우리 F6 세션 복원에 직접 적용된다 |
| 6 | **워크트리 지문 게이트** — `git worktree list` 가 호출당 **메인 스레드 2.69ms 동기 정지**인데, `<commonDir>/worktrees` 를 stat/readdir 로 요약하는 지문은 **0.01ms** 다(`fs/promises` 는 libuv 스레드풀로 빠진다, `uv_spawn` 은 아니다). 지문이 같으면 스캔을 건너뛴다. **규모를 안 타고 그대로 이식된다** | 우리가 `git worktree list` 를 타이머로 돌린다면 직행 |
| 7 | **`GitCapabilityCache`** — *"`git --version` 파싱만으로 분기하지 마라. 벤더 빌드가 백포트하고, 래퍼가 WSL·SSH 안에서 쓰이는 실제 바이너리와 다른 버전을 보고한다. **동작 프로브 + 정확한 폴백**이 최종 권위다."* 능력 상태는 **실행 호스트별로** 범위를 나눈다 | 우리는 서버마다 git 버전이 다르다 |

### xterm 에서 배울 것 (패치는 안 가져와도 된다)

- **`SortedList` 상류 버그**: 키가 바뀐 뒤(마커를 dispose 하면 정렬 키인 `line` 이 -1 이 된다)
  삭제 대기 항목이 배열 순서를 깨서 이진 탐색이 **있는 값을 못 찾는다** → `onDecorationRemoved` 가
  안 불려 **데코레이션이 영원히 그려진다.** xterm 데코레이션/마커를 쓰면 우리도 이 버그가 있다.
- **한글 IME — 이게 저쪽 패치의 절반이다.** 조합 시작 시점의 PTY 신원을 잡아 두고,
  `compositionend` 때 그 사이 PTY 가 바뀌었으면(분할·재부착·SSH 재접속·세션 복원)
  **커밋을 버린다.** 안 그러면 완성된 한글 음절이 **엉뚱한 셸로 들어간다.**
  → 불변식만 가져오면 된다: *조합 시작에 PTY 신원을 잡고, 바뀌었으면 커밋을 거부한다.*
- `serialize()` 는 파서의 부분 이스케이프 상태를 잃는다 — "터미널을 스냅샷한다"는 꼬리를 따로
  추적하지 않으면 불완전하다.

## 9. 확인 못 한 것

- **아무것도 실행하지 않았다.** 성능 수치는 전부 저쪽 문서·주석 인용이다.
- `orca-runtime.ts` 는 **42,363줄**이다. 그 안은 인용한 호출부 말고는 안 봤다.
- 모바일 동반앱의 상태 구독 경로(`mobile/` 은 별도 워크스페이스).
- Codex/Claude **계정 핫스왑** 흐름(트리거만 찾았고 `$HOME` 미러링 서비스는 안 읽었다).
- 저쪽 SSH 재접속의 체크포인트 복구가 **한 번도 실행된 적 없다**고 자기 문서가 적고 있는데
  (`ssh-reconnect-source-recovery.md`, 재접속 클라이언트가 `clientId` 를 유지해 `activate()` 가
  `'existing'` 으로 단락된다), 제안된 수정이 반영됐는지는 정적으로 판단 불가.
- `git-exec-validator.ts` 의 16개 서브명령에 대한 적대적 검토는 별도 작업이다.
