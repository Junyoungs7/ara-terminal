원격 서버에서 계속 실행

아라는 개발 서버에서 돌리는 Claude·Codex 가 PC 연결이 끊겨도 죽지 않도록 서버에 작은 도우미 프로그램(데몬)을 둡니다. 쓰고 싶은 서버에만 켜는 선택 기능이고, 서버 계정과 로컬 계정은 따로 쓸 수 있습니다. (2.2.12 부터)

1. 왜 서버에 데몬을 두나

SSH 로 서버에 붙어 Claude 를 돌리면 Claude 는 그 연결에 매달려 있습니다. PC 를 끄거나, 노트북을 덮거나, 와이파이·VPN 이 잠깐 끊기면 서버의 Claude 도 같이 끝나고 하던 일이 멈춥니다. 데몬은 연결과 상관없이 서버에서 계속 돌게 붙잡아 둡니다.

상황데몬 없이 (일반 SSH)데몬 있음 (관리형 서버)
PC 를 끄거나 절전서버의 에이전트도 끝남서버에서 계속 진행
와이파이·VPN 끊김끝남, 처음부터 다시자동으로 다시 붙고 화면도 이어짐
다음 날 · 다른 PC 에서이어 볼 방법 없음[서버 세션] 화면·F1 에서 붙어 이어 봄
일하는 중 · 승인 대기 표시안 보임로컬과 똑같이 보임
승인 카드 · Windows 알림 · 채팅 보기없음로컬과 똑같이 됨
한도에 걸려 다른 계정으로직접 다시 로그인같은 대화를 다른 계정으로 이어 감

원리는 서버에서 tmux 를 띄워 두고 쓰는 것과 같습니다. 아라는 그 위에 상태 표시·승인·알림·계정 전환을 얹었습니다.

2. 서버에 무엇이 남나

항목내용
실행 계정 · 권한접속한 SSH 계정 그대로. root·sudo 를 쓰지 않습니다.
네트워크포트를 열지 않습니다. PC 와는 기존 SSH 연결 안에서만 이야기합니다.
서비스 등록없음(systemd·cron 안 씀). 서버가 재부팅되면 멈추고 저절로 살아나지 않습니다.
파일그 계정 홈의 ~/.ara-server 한 폴더(본인만 읽기·쓰기, 권한 700). 필요한 것은 서버의 python3 하나.
설치 · 제거처음 연결할 때 설명을 보여 주고 동의를 받은 뒤 설치합니다. 설정 › 관리형 서버 › [제거] 하면 서버 계정 정보까지 흔적 없이 지웁니다.

3. 꼭 써야 하나

아닙니다. 데몬 없이 일반 SSH 터미널에서 Claude 를 그대로 써도 됩니다 — 연결이 끊기면 같이 끝나는 것만 감수하면 됩니다. 관리형 서버로 등록한 서버만 데몬을 쓰고, 서버마다 끄고 켤 수 있습니다(설정 › 관리형 서버, 상주 모드 기본 켜짐).

권장: 운영 서버가 아니라 개발 서버에서만 쓰세요. 서버 계정 정보(Claude 로그인)를 그 서버에 두기 때문입니다.

4. 서버·로컬 계정 따로 쓰기

됩니다. 로컬 계정과 서버 계정은 저장되는 곳부터 다릅니다.

로컬서버
등록하는 곳설정 › 사용량·계정설정 › 관리형 서버 › 서버 계정 (서버마다)
저장 위치이 PC그 서버의 ~/.ara-server/accounts
여러 계정 · 전환됨됨 — 한도에 걸리면 같은 대화를 다른 계정으로 이어 감
예개인 계정개발 서버 A 는 팀 계정, B 는 다른 계정

SSH 로그인 계정(예: dev, deploy)도 서버마다 따로입니다. 데몬은 그 SSH 계정으로 돌기 때문에 계정끼리 섞이지 않습니다.

5. 확인 상태

  • 시험용 서버(사내 PC 의 SSH·WSL)에서 설치·실행·끊김 뒤 재접속·다른 PC 에서 이어 보기·서버 계정 전환·제거까지 자동 시험이 모두 통과했습니다.
  • 아직 안 한 것: 실제 회사 개발 서버에서의 첫 연결과 서버에서의 claude 로그인. 다음 단계로 개발 서버 한 대에서 함께 확인합니다.
  • Codex 는 대화 번호를 알 수 없어 계정을 바꾸면 새 대화로 시작합니다.
