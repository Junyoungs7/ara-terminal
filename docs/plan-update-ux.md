## #197 버전 칸을 늘 누를 수 있게

### 무엇이 달라지나

```
지금   v1.0.9              ← 글자. 눌러도 아무 일 없음
바꿈   v1.0.9  (누름)      → 확인 중… → 토스트
                              · 최신이면  "최신 버전입니다 (1.0.9)"
                              · 있으면    "1.1.0 이(가) 나왔습니다  [받기]"
                              · 실패하면  "확인하지 못했습니다 — 사내망인지 보세요"
```

새 판이 있을 때의 동작은 **지금 그대로 둔다**(`↑ 1.1.0 있음` / `↓ 42%` / `✓ 준비됨`). 이번에 채우는
것은 **`idle`·`error` 일 때의 빈칸**이다.

### 어떻게

1. **`updateSeg` 에 `action: 'check'` 를 더한다**(`store/updateNotify.ts`).
   지금 `idle`·`error`·`checking` 은 `action: null` 로 떨어진다 — `checking` 만 `null` 로 남기고
   (확인 중에 또 누르면 안 된다) 나머지는 `'check'`.
   ⚠️ **순수 함수라 시험으로 못 박는다** — `tests/updateNotify.test.ts` 가 이미 상태별 표를 갖고 있다.
   그 표에 `action` 기대값이 이미 들어 있으니 **거기만 고치면 회귀가 잡힌다.**

2. **`runUpdateAction` 에 `'check'` 갈래**(같은 파일). `window.ev.app.updateCheck()` 를 부르고,
   **결과는 상태 구독으로 온다**(`update:state`) — 여기서 기다리지 않는다.

3. **토스트.** 이미 `MainArea.toast(msg)` 가 있고 Shell 이 여러 곳에서 쓴다(`Shell.tsx:795` 등).
   새 토스트 장치를 만들지 않는다.
   ⚠️ **어디서 띄우나가 판단 지점이다.** `checking` → `idle|available|error` 로 **바뀌는 순간**에만
   띄워야 한다. 상태가 올 때마다 띄우면 6시간 주기 확인에도 토스트가 뜬다.
   → `useUpdateState` 를 쓰는 자리에서 **직전 상태가 `checking` 이었나**를 ref 로 들고 가른다.
   그리고 **사람이 눌러서 시작한 확인일 때만** — 주기 확인은 조용해야 한다. 그 구분을 위해
   `runUpdateAction('check')` 가 "내가 시작했다" 표시를 세운다.

4. **`available` 토스트에는 [받기] 버튼**을 단다. 토스트에 동작 버튼이 있던 적이 없으면
   **없는 장치를 새로 만들지 말고** 문구만 띄우고 상태바 칸이 `↑ 1.1.0 있음` 으로 바뀌는 것에
   맡긴다(그 칸은 이미 눌러서 받을 수 있다). **먼저 토스트 구현을 읽고 정한다.**

### 시험
- 순수: `updateSeg` 의 `action` 표(6상태) · "누가 시작한 확인인가" 판정
- ⚠️ 토스트가 **주기 확인에서는 안 뜨는 것**을 시험으로 못 박는다 — 이게 이 항목에서 제일
  귀찮아질 수 있는 실패다(6시간마다 토스트가 뜨면 그게 다음 제보다)

## #198 업데이트 중이라는 것을 보여 준다

### 🔴 먼저 — 못 하는 것을 분명히 한다

```
[받는 중]        앱이 살아 있다        → 우리가 그릴 수 있다 ✅
[설치 중]        앱이 없다             → 🔴 우리가 그릴 수 있는 것이 없다
[다시 뜬 뒤]     앱이 살아 있다        → 그릴 수 있다 ✅
```

`quitAndInstall(true, true)` 는 설치 프로그램을 띄우고 **우리를 종료시킨다.** 그 사이 우리 프로세스는
존재하지 않는다 — **"작은 로고 + 퍼센트"를 설치 중에 띄우는 것은 이 구조에서 불가능하다.**
(1.0.6 에서 없앤 NSIS 창이 바로 "설치 중에 뜨는 화면"이었다. 그것을 되돌리는 것은 답이 아니다 —
준영님이 그걸 없애 달라고 하셨다.)

**그래서 할 수 있는 것은 셋이고, 그것으로 충분하다:**

### ① 받는 동안 — 진행률을 눈에 띄는 자리로

지금 진행률은 상태바 구석의 `↓ 42%` 뿐이다. 받기를 누른 사람이 **그 칸을 계속 보고 있지 않다.**
→ 받기를 시작하면 **로고 + 진행 막대**를 띄운다. 자리 후보 둘:
- **(가) 켤 때 뜨는 창 자리 재사용** — `useUpdatePrompt` 의 다이얼로그가 이미 그 모양이다.
  [받기]를 누르면 창이 닫히는 대신 **진행 막대로 바뀐다.** 새 컴포넌트 0.
- (나) 우하단 토스트에 막대 — 작고 덜 방해되지만 **로고를 넣을 자리가 아니다.**

→ **(가)를 권한다.** 준영님 말씀의 "작은 로고가 뜨면서 퍼센트"에 가장 가깝고, 이미 있는 창이다.

### ② 끄기 **직전** — 무슨 일이 일어나는지 말한다

[다시 시작하여 설치]를 누르면 **창이 사라지기 전에** 같은 창을 이렇게 바꾼다:

```
        [로고]
   업데이트를 설치하고 있습니다
   잠시 후 아라가 저절로 다시 열립니다
   (이 창은 곧 닫힙니다 — 기다리지 않으셔도 됩니다)
```

⚠️ **한 박자 뒤에 `quitAndInstall` 을 부른다.** 지금은 부르는 순간 창이 사라져 이 문구가 렌더될
틈이 없다. 얼마나 기다릴지는 **재서 정한다**(그릴 시간만큼 — 길면 사용자가 멈춘 줄 안다).

### ③ 설치가 끝난 뒤 — 새 판으로 왔다고 말한다

`isForceRunAfter: true` 라 앱이 저절로 다시 뜬다. 그때 **"1.1.0 으로 업데이트되었습니다 [패치 내역]"**
토스트를 한 번 띄운다.
→ 판정은 **순수 함수**로: 저장된 "마지막으로 본 버전" ≠ 지금 버전이면 한 번 띄우고 값을 갱신한다.
⚠️ 저장 자리는 `localStorage`(스누즈와 같은 이유 — 설정이 아니라 잠깐의 기억이고
`SCHEMA_VERSION` 을 건드릴 이유가 없다).

### 시험
- 순수: "새 판으로 왔나" 판정(같은 버전이면 안 띄운다 · 저장값이 없으면 **안 띄운다** —
  처음 깐 사람에게 "업데이트되었습니다"는 거짓말이다)
- ⚠️ 끄기 직전 문구는 **실기 확인 항목**이다. 창이 사라지는 타이밍이라 하네스로 못 잡는다
