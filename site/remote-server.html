원격 서버에서 계속 실행

아라는 개발 서버에서 돌리는 Claude·Codex 가 PC 연결이 끊겨도 죽지 않도록 서버에 작은 도우미 프로그램(데몬)을 둡니다. 쓰고 싶은 서버에만 켜는 선택 기능이고(tmux 를 그대로 써도 됩니다), 서버 계정과 로컬 계정은 따로 쓸 수 있습니다. (2.2.12 부터)

1. 왜 서버에 데몬을 두나

SSH 로 서버에 붙어 Claude 를 돌리면 Claude 는 그 연결에 매달려 있습니다. PC 를 끄거나, 노트북을 덮거나, 와이파이·VPN 이 잠깐 끊기면 서버의 Claude 도 같이 끝나고 하던 일이 멈춥니다. 데몬은 연결과 상관없이 서버에서 계속 돌게 붙잡아 둡니다.

상황데몬 없이 (일반 SSH)데몬 있음 (관리형 서버)
PC 를 끄거나 절전서버의 에이전트도 끝남서버에서 계속 진행
와이파이·VPN 끊김끝남, 처음부터 다시자동으로 다시 붙고 화면도 이어짐

원리는 서버에서 tmux 를 띄워 두고 쓰는 것과 같습니다. 아라는 그 위에 상태 표시·승인·알림·계정 전환을 얹었습니다.

2. tmux 와 무엇이 다른가

끊겨도 살려 두는 것은 tmux 와 같습니다. 데몬도 tmux 처럼 접속한 SSH 계정으로 도는 프로세스 하나입니다(root·포트·서비스 등록 없음). 다른 점은 화면만 읽지 않고 Claude 가 직접 보내는 신호(승인 대기·답 끝남·대화 파일 위치)를 받아 PC 로 넘긴다는 것입니다.

tmux아라 데몬
끊겨도 살아 있음됨됨
서버에 필요한 것tmux 설치(없으면 관리자 권한으로 설치)python3 하나(대부분 기본 설치)
일하는 중 · 승인 대기 판단화면을 긁어서 추측Claude 가 보내는 이벤트가 먼저, 화면은 보조
Claude 가 업데이트돼 화면 모양이 바뀌면상태 표시 전체가 틀어짐이벤트로 받는 상태는 그대로, 화면에 기대는 부분만 손봄

아라 터미널 안에서 스크롤 · 복사tmux 자체 스크롤 · 단축키와 부딪힘아라 터미널 그대로
실제 사례: 2026-11-05 Claude Code 2.1.300 은 입력 줄 머리 글자를 ❯ 에서 > 로 바꿨습니다. 아라에서도 화면을 보조로 읽던 부분(채팅 보기에서 글 넣기)이 그날 바로 멈췄습니다(2.2.16 에서 고침). 화면에만 기대면 CLI 가 바뀔 때마다 상태 표시 전체가 이렇게 깨집니다.

이 차이는 상태 표시·알림이 필요할 때 이야기입니다. 터미널만 쓰면 되면 tmux 를 그대로 쓰셔도 됩니다 — 4. 꼭 써야 하나.

3. 서버에 무엇이 남나

항목내용
실행 계정 · 권한접속한 SSH 계정 그대로. root·sudo 를 쓰지 않습니다.
네트워크포트를 열지 않습니다. PC 와는 기존 SSH 연결 안에서만 이야기합니다.
서비스 등록없음(systemd·cron 안 씀). 서버가 재부팅되면 멈추고 저절로 살아나지 않습니다.
파일그 계정 홈의 ~/.ara-server 한 폴더(본인만 읽기·쓰기, 권한 700). 필요한 것은 서버의 python3 하나.
설치 · 제거처음 연결할 때 설명을 보여 주고 동의를 받은 뒤 설치합니다. 설정 › 관리형 서버 › [제거] 하면 서버 계정 정보까지 흔적 없이 지웁니다.

4. 꼭 써야 하나

아닙니다. 쓰는 방식은 사람마다 고르면 됩니다. 아래 셋 다 괜찮습니다.

  • 평소처럼 tmux: 아라든 다른 터미널이든 SSH 로 서버에 붙어 tmux 안에서 Claude 를 돌리세요. 끊겨도 살아 있고, 다시 붙으면 이어집니다. 아라는 그냥 터미널로만 쓰게 됩니다.
  • 그냥 SSH: 데몬도 tmux 도 없이 바로 써도 됩니다. 연결이 끊기면 같이 끝나는 것만 감수하면 됩니다.
  • 관리형 서버(데몬): 상태 표시·승인 카드·알림·채팅 보기·계정 전환까지 로컬처럼 쓰고 싶을 때 켭니다.

관리형 서버로 등록한 서버만 데몬을 쓰고, 서버마다 끄고 켤 수 있습니다(설정 › 관리형 서버, 상주 모드 기본 켜짐).

권장: 운영 서버가 아니라 개발 서버에서만 쓰세요. 서버 계정 정보(Claude 로그인)를 그 서버에 두기 때문입니다.

5. 서버·로컬 계정 따로 쓰기

됩니다. 로컬 계정과 서버 계정은 저장되는 곳부터 다릅니다.

로컬서버
등록하는 곳설정 › 사용량·계정설정 › 관리형 서버 › 서버 계정 (서버마다)
저장 위치이 PC그 서버의 ~/.ara-server/accounts
여러 계정 · 전환됨됨 — 한도에 걸리면 같은 대화를 다른 계정으로 이어 감
예개인 계정개발 서버 A 는 팀 계정, B 는 다른 계정

한도에 걸렸을 때 다른 계정으로 이어 가는 방법: 토큰을 옮기거나 넣지 않습니다. 계정마다 로그인 폴더가 따로 있고(처음 한 번 그 폴더로 claude 로그인), 전환하면 아라가 지금 Claude 를 끝내고 다른 계정 폴더로 claude --resume <대화 id> 를 다시 띄웁니다. 대화 기록 폴더는 계정끼리 같이 쓰기 때문에 새 계정에서도 같은 대화가 그대로 이어집니다. 로그인 정보는 각 폴더 안에만 있고 아라가 꺼내 보지 않습니다.

SSH 로그인 계정(예: dev, deploy)도 서버마다 따로입니다. 데몬은 그 SSH 계정으로 돌기 때문에 계정끼리 섞이지 않습니다.

6. 확인 상태

  • 시험용 서버(사내 PC 의 SSH·WSL)에서 설치·실행·끊김 뒤 재접속·다른 PC 에서 이어 보기·서버 계정 전환·제거까지 자동 시험이 모두 통과했습니다.
  • 아직 안 한 것: 실제 회사 개발 서버에서의 첫 연결과 서버에서의 claude 로그인. 다음 단계로 개발 서버 한 대에서 함께 확인합니다.
  • Codex 는 대화 번호를 알 수 없어 계정을 바꾸면 새 대화로 시작합니다.
