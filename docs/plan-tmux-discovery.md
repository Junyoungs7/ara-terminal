# 계획 — tmux 를 외우지 않고 쓰게 (#200)

준영님이 전한 다른 개발자 피드백(2026-09-15):
> *"tmux 를 사용할 때 tmux 내의 pane, 마우스 사용해서 분할창 이동, 메인 창으로 이동 등 다양한
> 기능을 단축키로 제공하는데 이걸 일일이 다 검색해서 찾기가 어렵다고 하더라고."*

---

## 지금 있는 것 — 생각보다 많다 (코드로 확인함)

| 자리 | 무엇 |
|---|---|
| `shared/tmux.ts` | **입력 매크로** 여섯: `new` · `list` · `attach` · `detach` · `nextWindow` · `prevWindow`. prefix(`\x02`) + 키를 흘려보낸다 |
| `shared/tmuxList.ts` | 세션 목록 조회 + **설치 안 됨 감지** |
| `interactions/actions.tsx:347` | 터미널·트리 우클릭 ▸ **tmux 하위 메뉴**(새 세션 · 세션 목록 · 분리 · 창 이동). 없는 서버에선 **눌리지 않게** 막아 뒀다 |
| `data/commandBook.ts:163~` | 명령책 **tmux 갈래 10항목** — `Ctrl+b %`·`"`(분할), `Ctrl+b 방향키`(pane 이동)까지 **글로는 다 있다** |

**즉 빠진 것은 지식이 아니라 손이다.** 명령책에 적힌 pane 조작이 **메뉴에는 없다** — 우클릭
메뉴는 창(window) 단위까지만 있고 pane 은 사용자가 외워서 `Ctrl+b` 를 쳐야 한다.
그리고 **마우스 모드**(`set -g mouse on`)는 어디에도 없다 — 피드백이 "마우스 사용해서 분할창 이동"을
콕 집은 이유가 그것이다.

---

## 무엇을 더하나 — 셋. 크기 순

### ① pane 조작을 우클릭 메뉴에 (S) — **가장 값싸고 가장 크다**

`tmuxMenuItem` 의 하위 메뉴에 pane 갈래를 더한다. 매크로는 `tmux.ts` 에 **한 줄씩** 추가된다
(이미 있는 `nextWindow` 와 같은 모양 — prefix + 키 하나):

| 항목 | 보낼 키 | 힌트에 적을 것 |
|---|---|---|
| 세로로 나누기 | `Ctrl+b %` | `Ctrl+b %` |
| 가로로 나누기 | `Ctrl+b "` | `Ctrl+b "` |
| 다음 칸으로 | `Ctrl+b o` | `Ctrl+b o` |
| 칸 옮겨 다니기 ▸ ←↑↓→ | `Ctrl+b` + 방향키 | `Ctrl+b 방향키` |
| 이 칸 닫기 | `Ctrl+b x` | `Ctrl+b x` · ⚠️ **확인을 묻는다**(되돌릴 수 없다) |
| 이 칸만 크게 / 되돌리기 | `Ctrl+b z` | `Ctrl+b z` |

🔴 **메뉴에 실제 키를 힌트로 적는다.** 이게 이 라운드의 핵심이다 — 메뉴는 **지금 한 번** 해결해
주고, 힌트는 **다음번에 메뉴를 안 열게** 만든다. 기존 tmux 메뉴가 이미 그 방식이고
(`actions.tsx:375` 주석: *"힌트에 실제 키를 적는다 — 메뉴를 한 번…"*) 그 판단을 pane 으로 넓히는 것뿐이다.

⚠️ `Ctrl+b x` 는 **묻는다.** 다른 다섯은 되돌릴 수 있지만 이것만 내용을 잃는다.
⚠️ 설치 안 된 서버에서 **눌리지 않게** 하는 기존 `off` 게이트를 그대로 탄다.

### ② 마우스 모드 토글 (S~M) — 피드백이 콕 집은 것

`tmux` 는 기본이 마우스 꺼짐이다. 켜면 **칸을 클릭해 옮겨 다니고, 경계를 끌어 크기를 바꾸고,
휠로 스크롤**할 수 있다. 다른 개발자가 원한 "마우스로 분할창 이동"이 정확히 이것이다.

- 메뉴에 **[마우스 켜기/끄기]** 한 항목. 보내는 것은 `tmux set -g mouse on｜off` (명령줄이라 `\r` 붙임)
- 🔴 **상태를 우리가 기억하지 않는다.** `tmux` 가 진짜 주인이고 우리는 매크로만 보낸다
  (`tmux.ts` 머리 주석의 원칙). 라벨은 "마우스 켜기/끄기" 한 항목으로 두고 **토글 표시를 안 한다** —
  틀린 표시를 하느니 안 하는 게 낫다. 결과는 터미널 화면이 말한다.
- ⚠️ **대가를 문구로 알린다**: 마우스를 켜면 **터미널에서 드래그 복사가 tmux 에게 먹힌다**
  (Shift 를 누르고 드래그하면 예전처럼 된다). 이걸 안 적으면 그게 다음 제보다.

### ③ 치트시트에 tmux 갈래 (S)

`Cheatsheet.tsx` 가 이미 있다(단축키 목록). 거기 **tmux 절**을 더한다 — 명령책은 "검색해서 찾는"
자리고 치트시트는 "펼쳐 놓고 보는" 자리다. 피드백이 *"일일이 다 검색해서 찾기가 어렵다"* 였으니
**검색하지 않고 한눈에 보이는 자리**가 빠진 것이다.

⚠️ **명령책과 내용을 두 벌로 두지 않는다.** `commandBook.ts` 의 tmux 10항목이 이미 진실이다 —
치트시트가 그 데이터를 읽어 그린다. 두 벌이 되면 한쪽만 낡는다.

## 안 하는 것 (지금은)

| 무엇 | 왜 |
|---|---|
| **tmux 상태를 화면에 그리기**(창·칸 목록을 GUI 트리로) | `tmux.ts` 가 *"tmux 프로토콜을 파싱하지 않는다"* 를 설계로 못박았다. control mode(`tmux -CC`)를 물면 그 약속이 깨지고 파싱·동기화 버그를 통째로 떠안는다. **F24~F27(데몬)이 먼저다** |
| 미니 프리뷰가 맨 아래 칸만 보여 주는 것(#191) | 별개 항목. 이 라운드와 파일이 겹치지만 원인이 다르다 |
| prefix 를 `Ctrl+a` 로 바꾸기 | 사용자 `.tmux.conf` 를 우리가 고치는 일이다. **남의 설정을 건드리지 않는다** |
| 우리 단축키로 tmux 조작(예: `Alt+화살표`) | 우리 키맵과 원격 tmux 가 충돌한다. 메뉴 + 힌트로 먼저 재 보고, 그래도 불편하다는 말이 나오면 그때 |

## 시험

- 순수: `tmux.ts` 의 새 액션들이 **정확한 바이트**를 만드는가(prefix `\x02` + 키, **개행 없음**).
  기존 `tests/` 에 tmux 매크로 시험이 있으면 거기에 더한다 — 새 파일을 만들기 전에 찾는다.
- ⚠️ 마우스 토글은 **명령줄**이라 `\r` 이 붙는다 — 매크로 여섯과 규칙이 다르다. 그 차이를 시험이
  말하게 한다(안 그러면 다음 사람이 통일한다고 고쳤다가 깨뜨린다).
- 메뉴 항목이 **설치 안 된 서버에서 전부 비활성**인지 — 기존 `off` 게이트에 새 항목이 딸려 가는지
  확인한다(빠뜨리기 쉬운 자리다).
- 🔴 **실기 확인**: 진짜 tmux 에 붙어서 여섯 동작이 실제로 먹는지. 하네스는 pty 를 안 띄운다.

## 🔴 더 넓게 볼 것 (2026-09-15 준영님: *"저거 외에도 여러 기능들이 있잖아. 그 기능들을 GUI 로 제공하는 방향을 조금 더 모색해보자"*)

위 셋은 **제일 값싼 것부터** 적은 것이고, 준영님이 원하시는 것은 그보다 넓다.
**이름 변경(#199)이 끝난 뒤 이 문서를 다시 열어 아래를 채운다.**

채울 때 답할 것:
- **tmux 의 전체 표면을 먼저 센다** — 세션·창·칸 말고도 있다: 복사 모드(스크롤백 검색·선택),
  동기화 입력(`setw synchronize-panes` — 여러 칸에 같은 명령), 레이아웃 프리셋(`Ctrl+b Space`),
  칸 크기 조절, 창 이동·재정렬, 세션 간 창 옮기기, `Ctrl+b ?`(키 목록), 이름표.
  **무엇이 GUI 로 값이 있고 무엇이 키가 더 빠른지**를 갈라야 한다 — 전부 버튼으로 만들면
  메뉴가 30줄이 되고 그건 검색만큼 못 찾는다.
- **어디에 두나** — 우클릭 메뉴 하나로는 넘친다. 후보: 터미널 위 얇은 **tmux 바**(붙어 있을 때만
  나타남) · 사이드바 [AI] 옆의 tmux 탭 · 하단 패널의 한 탭. **자리를 정하는 것이 이 라운드의 절반이다.**
- 🔴 **파싱 없이 어디까지 되나** — 지금 설계는 "매크로만 보낸다"다. 칸 목록을 **그리려면**
  `tmux list-panes` 를 읽어야 하고, 그 순간 "상태를 우리가 안다"는 주장이 시작된다.
  그 선을 어디에 그을지가 이 기능의 성격을 정한다(읽기만 하고 **보여 주기 전용**으로 두는 길도 있다).
- **동기화 입력은 위험하다** — 여러 서버 칸에 같은 명령이 들어간다. 켜져 있다는 것을 **화면이
  계속 말해야** 하고, 껐는지 확인하지 않고 명령을 치면 사고가 난다.

## 순서 권고

**① → ③ → ②.** ①이 제일 값싸고 크다(메뉴 + 힌트). ③은 ①의 내용을 재사용하니 그다음.
②는 대가(드래그 복사)를 문구로 정리해야 해서 마지막 — 그리고 ②는 **한 번 켜 보시고 판단**하실
여지가 있다(마우스를 켜는 게 늘 좋은 건 아니다).
