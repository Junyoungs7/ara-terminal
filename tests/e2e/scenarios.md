## 21. 파일 Ctrl+V → SFTP 업로드 (W1 F14, 2026-08-09 다중 선택 해소)

**받는 경로가 바뀌었다.** 전에는 Ctrl+V 키다운을 가로채 Electron clipboard API 로 경로를 읽었는데,
Windows 에서 그 API 는 **파일 하나만** 준다(CF_HDROP 은 번호 형식이라 이름으로 못 집고, 경로 한 개짜리
`FileNameW` 로 대신 읽었다). 가로채는 순간 브라우저 paste 이벤트까지 함께 막혀 정작 전부 알고 있는 쪽을
못 쓰고 있었다 — 그게 A-3(첫 파일만 올라감)의 진짜 원인이다. 실측 결과:

| 읽는 방법 | 파일 2개를 복사했을 때 |
|---|---|
| `clipboard.readBuffer('FileNameW')` | 1개 |
| `availableFormats()` 의 `text/uri-list` | 형식만 광고하고 읽으면 **빈 값** |
| PowerShell `Get-Clipboard -Format FileDropList` | 2개 (367ms + 프로세스 기동) |
| **브라우저 paste 이벤트** | **2개 + 실경로(Electron `File.path`)** ← 채택 |

편집 불가 요소(파일 트리)에서는 이벤트가 요소가 아니라 **document 로만** 온다(실측) — 그래서 document
캡처 리스너 하나로 받고 대상은 포커스로 고른다(`src/renderer/store/pasteFiles.ts`). RDP 화면의 64MB 상한도
이때 없앴다(진짜 `File` 핸들이라 디스크에서 조각내 읽는다 — main 이 바이트를 통째로 들고 있던 IPC 제거).

자동화 주의: **합성 KeyboardEvent 로는 재현되지 않는다.** `paste.spec.ts` 는 paste 이벤트를 직접 만들어
document 에 넣고(파일), 텍스트는 실제 클립보드 + Playwright 의 신뢰된 Ctrl+V 로 쏜다.

> **경계와 창, 둘 다 붙었다(2026-08-09).** 아래는 그때 확인한 사실과 지금 구조다.
>
> RDP 의 다중 모니터는 화면을 여러 개 보내는 게 아니다 —
> 서버는 **모니터 전체를 감싸는 사각형 하나**를 프레임버퍼로 그리고, 경계는 "여기가 경계다"라는
> 메타데이터로만 따로 알린다. 그래서 경계 없이도 펼치기 자체는 된다(mstsc 의 옛 `span monitors:i:1`
> 과 같은 모습). wasm 안에 경계 PDU 코드는 **이미 컴파일돼 있는데**(`ironrdp-pdu` 의
> `gcc/monitor_data.rs`·`monitor_extended_data.rs`, `ironrdp-displaycontrol` 의 `DisplayControlMonitorLayout`,
> 로그 문자열 "Sending monitor layout" 까지 확인) JS 로 나오는 구멍이 없다. 확장 디스패치가 받는
> ident 는 이게 전부다(wasm 바이너리에서 확인):
> `pcb · kdc_proxy_url · display_control · enable_credssp · outbound_message_size_limit ·
> files_available_callback · file_contents_request_callback · file_contents_response_callback ·
> lock_callback · unlock_callback · locks_expired_callback · print_job_stream_callback`
> — monitor 계열이 없었다. **그래서 포크했다**(`vendor/ara-multimonitor.patch`, 기준 커밋 210f1d3):
> connector 의 `Config.monitors` → GCC 요청, wasm 의 `monitors` 확장 ident, TS 의 `monitorLayout()`.
> rustup 1.94.1 + wasm-bindgen-cli 0.2.126 으로 빌드했고 **DLP 는 막지 않았다**(crates.io 웹의 403 은
> UA 차단이고 실제 다운로드 경로는 열려 있다). 재빌드 절차는 `vendor/README.md`.
>
> **창 분리**는 프레임버퍼가 하나라는 제약 위에서 푼다. `window.open()` 으로 연 창이 **같은
> 프로세스·같은 오리진**이라(file:// 포함, 실측) 부모가 자식 캔버스에 `drawImage` 로 직접 그릴 수
> 있다 — 매 프레임 IPC 로 픽셀을 나르지 않는다. 주 모니터는 부모 창이 음수 마진으로 잘라 보여 주고
> (복사조차 없다), 나머지는 자식 창이 rAF 루프로 복사한다. 자식 창의 입력은 원격 좌표로 환산해
> 부모의 세션으로 넘긴다.
>
> 계산은 `src/shared/rdpSpan.ts`(좌표계가 둘 — 원격은 주 모니터 원점, 잘라오기는 감싸는 사각형
> 원점), 단위 검증은 `tests/rdpSpan.test.ts`(22건)·`tests/rdpSpanWindow.test.ts`(12건)·
> `tests/rdpMirror.test.ts`(8건).

> **CSP 주의**: `index.html` 의 `connect-src` 에 두 항목이 **꼭 있어야 한다**(둘 다 실측으로 확인 —
> 빼면 접속이 안 붙는다): `data:` = 공식 패키지가 wasm 을 base64 data URL 로 내장해서, `ws://127.0.0.1:*`
> = 렌더러가 main 의 로컬 릴레이(`builder.proxyAddress`)에 웹소켓으로 붙어서. CSP 를 건드리는 변경이
> 들어오면 여기부터 의심할 것.

> 언마운트**됐다 — 탭·경로·표의 정렬·검색이 통째로 날아갔다. 우측 레일이 상태를 지키는 것과

> `visible` 을 `active` 에 함께 곱한다(숨은 탭이 명령을 안 보내던 기존 규칙과 같은 결).

> **#69(2026-08-14) — 아홉 칸이 똑같이 생겼는데 넷이 콘솔을 닫았다.** 준영님 지적:

> ① **[파일] 은 콘솔 안 탭**이 됐다 — 떠 있는 탐색기가 쓰는 `FileTree` 를 그대로 끼운다(새 구현 0줄).

> ② **[로그]·[포트] 는 콘솔을 닫지 않는다.** 대신 타일에 ↗ 를 달아 누르기 전에 알린다.
> ③ **[터미널] 만 콘솔을 닫는다** — 세션을 만드는 동작이라 터미널이 보여야 한다.

## 37. AI CLI 한 번에 시작 (F27, 신설)

서버 접속 → 폴더 이동/생성 → `claude --dangerously-skip-permissions -r` 세 단계를 진입점 하나로
끝낸다. 완료 보고 `agent_talk/F27-done.md`(설계 배경 `agent_talk/F27-task.md` §0), 캡처
`agent_talk/F27-screenshot.png`.

진입점은 **네 곳**이다 — 탭바 ＋ 드롭다운(AICLI-1) · 단축키 `Ctrl+Shift+L`(AICLI-2) · 원격 폴더
우클릭(AICLI-4) · 서버 트리 우클릭(AICLI-3).

**"보낼 명령" 줄은 실제 전송 문자열과 글자 하나 다르지 않다**(AICLI-5★ — ssh2 하네스가 shell 채널로
받은 바이트와 대조한다). 그 줄이 `cd ~/'projects/신규 작업' && claude --dangerously-skip-permissions -r`
꼴인 이유가 있다 — **물결표(`~`)는 따옴표 밖에 있다.** 작은따옴표 안에 넣으면(`cd '~/x'`) 셸이 홈으로
펼치지 않아 "그런 폴더 없음"이 된다(목업 초안 `agent_talk/F27-task.md` §1 은 이 형태를 틀리게 적어
뒀었다 — 그대로 갔으면 기본 경로에서 매번 실패했을 것이다).

CLI 가 없는 서버면 **안내가 뜨고 원격에는 아무것도 나가지 않는다**(AICLI-7★ — 판정은 화면이 아니라
하네스가 받은 입력 바이트 수, 0이어야 한다).

최근 목록은 **[시작]이 성공한 뒤에만 저절로 쌓인다** — 창에 저장 버튼이 없다. "저장이 전제가 되면
안 된다"는, 한 번 반려된 설계(작업 프로필에 실행 명령을 얹는 안)의 결론이다(`F27-task.md` §0): 처음
쓰는 사람도 아무것도 저장해 두지 않은 채로 바로 시작할 수 있어야 한다. 최근 항목을 눌러도 바로
실행되지 않고 폼만 채운다(AICLI-6).

## 38. UI 글자 크기 · 배율 (UI-font5, 2026-08-11 신설)

준영님: **"폰트가 작아서 살짝 가독성이 떨어지는데 ui에 사용되는 폰트 크기 키워주고 폰트가 커짐에
따라 잘리지 않게 해주고."**

UI 크롬 글자 크기는 **UI-font1~3 에서 세 라운드를 실험하고도 코드에 적용된 적이 없었다**
(UI-font3 보고서: "이번 라운드는 코드 변경 없이 인라인 style로만 실험했음"). 이번에 적용했다.

**왜 그동안 못 키웠나**: `scripts/scan-magic-numbers.mjs` 의 검사 범위가 `components`·`interactions`
뿐이라 **`styles/` 가 통째로 빠져 있었다.** 그 사이 `shell.css`·`interactions.css` 에 `font-size`
리터럴이 **229곳, 12종**(9 / 9.5 / 10 / 10.5 / 11 / 12 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15.5px)으로
흩어져 한 번에 조절할 방법이 없었다. 척도 7단계(`--fs-micro`~`--fs-xl`)를 `tokens.css` 로 모으고,
**스캐너를 넓혀 다시 흩어지는 것을 막았다**(styles/ 의 font-size px 리터럴은 이제 게이트 실패).

- 본문 기준 **13.5px → 15px**. 하한을 세웠다 — **어떤 UI 글자도 11px 미만이 되지 않는다**
  (옛 9·9.5·10px 이 30곳 있었고 그게 "가독성이 떨어진다"의 실체였다).
- **행 높이도 같은 배율을 탄다**(`--row-titlebar`·`--row-statusbar`·`--row-tabbar`) — 글자만 키우면
  그 줄에서 잘린다. 글자를 담는 고정 높이 10곳은 `min-height` 로 바꿔 내용이 높이를 정하게 했다.
- **설정 [일반] → UI 글자 크기**(작게 / 보통 / 크게 / 아주 크게). 저장값은 숫자가 아니라 **이름**이라
  나중에 배율 수치를 다시 손봐도 고른 값이 산다. 터미널 글자는 이 배율을 타지 않는다(F5 자체 슬라이더).
- `transform: scale()` 은 쓰지 않는다 — 글자가 흐려진다.

**새 폴러를 만들지 않았다.** CPU·메모리·GPU 는 상태바 게이지가 이미 쓰는 `telemetry:data` 를 그대로

  **로컬 셸을 하나도 안 열어 둔 상태(SSH 만 쓰는 중)에서도** 보여야 해서 세션에 맬 수 없다.

그래프는 **차트 라이브러리 없이** 인라인 SVG `polyline` 이다. 표본 60개(2.5분) 링버퍼이고 **영속화하지
않는다** — 패널을 닫으면 버린다(오래된 값으로 "지금"을 그리지 않는다). 세션을 바꿔도 버린다: 이전
서버의 곡선을 새 서버 그래프에 이어 붙이면 거짓말이 된다.

**GPU 는 값이 올 때만 칸이 생긴다**(상태바 `gaugesOf()` 와 같은 규칙 — 없는 칸을 "—"로 남겨 두면
고장난 것처럼 보인다). 원격은 `nvidia-smi` 가 있으면 나오고, **내 PC 는 표시하지 않는다**:
Windows 에 무의존 조회 방법이 없고, 원격처럼 외부 명령을 내 PC 에서 주기적으로 실행하지는 않는다는
기존 판단(`LocalTelemetry.ts` 머리주석)을 유지했다. 그 자리에는 이유를 한 줄로 밝힌다.

사용률 톤(90% 빨강 / 75% 주황)은 **F26 디스크 창과 같은 경계**를 쓴다 — 같은 숫자가 화면마다 다른

## 40. AI 세션 패널 (F30, 2026-08-12 신설)

준영님: **"서버 3대에 Claude Code 를 띄워 두면 어느 놈이 승인을 기다리며 멈춰 있는지 모른다."**

`조용함 2분` / `출력 중` / `끝남 2분 전`. 행을 누르면 그 탭으로 간다.

**판정 근거는 "출력이 멎었다" 하나뿐이다.** 그래서 화면은 **관측한 사실만** 말한다 — "조용함 2분".
승인 대기일 수도, 60초 넘게 걸리는 빌드일 수도 있고 둘을 가를 방법이 마땅치 않다(원격 프로세스
상태를 봐도 대기와 수면이 안 갈린다). 추측("승인을 기다리는 중일 수 있습니다")은 알림 부제로 한 번만
덧붙이고, 패널 아래에 판정 근거를 밝힌다. **확신하는 척했다가 한 번 틀리면 그다음부터 아무도 이
표시를 안 믿고, 그러면 기능이 죽는다.**

기준 60초: 빌드·테스트가 30~60초 조용한 건 흔하고 진짜 승인 대기는 분 단위다. 써 보고 조정할 값이다.

**마지막 출력 시각은 main 이 센다**(`MainSessionManager.activity()` + `session:activity`).
화면에 안 보이는 탭은 `attached=false` 라 renderer 로 데이터가 안 나가는데, **조용한지 알고 싶은 건
정확히 그 안 보이는 탭들**이라 renderer 가 셀 수 없다. `session:list` 에 얹지 않은 이유는 그쪽이
workspace.json 으로 영속되는 타입이기 때문이다(매 출력마다 바뀌는 값을 넣으면 스냅샷이 늘 더럽다).

**패널을 닫아 두면 아무것도 안 보이는 것이 D안의 급소**였다 → 액티비티 바 아이콘에 점을 찍고,
OS 알림은 **앱이 뒤에 있을 때만**·세션당 한 번만 띄운다(앞에 있으면 점으로 충분하고, 알림이 겹치기
시작하면 그때부터 전부 무시하게 된다).

## 43. F32 세션 창 떼어내기 (2026-08-17 신설)

준영님 요청: "창을 떼서 스플릿 뿐만 아니라 다른 모니터 혹은 창을 아예 분리하는거지. 그리고
거기에도 분할을 할 수 있게. 그 창에서도 따로 하단바가 보이는거지. 가능해?"

**가능했던 이유는 구조에 이미 있었다.** pty·SSH 세션은 main 프로세스에 살고(`MainSessionManager`)
렌더러는 IPC 로 화면만 받는다 — 그래서 창을 떼어내도 세션이 죽지 않고, "떼어내기"가
**소유 표시(`Session.winId`) 한 줄을 바꾸는 일**로 끝난다. 재접속도 화면 재생도 없다.

창 자체는 편집기(`#editor`)·다중 모니터 RDP(`#rdpwin`)와 **같은 방식**이다: 같은 렌더러 번들을
해시(`#sessionwin`)로 갈라 쓴다. 화면은 `MainArea` 를 그대로 재사용한다 — 그쪽 props 가 거의 다
optional 이라 이 창에 없는 기능(연결 관리자·아라·AI CLI)은 안 넘기면 된다. **분할과 하단바가
거기서 공짜로 따라온다** — 준영님 요청의 나머지 둘이 새 코드 없이 채워진 셈이다.

### 바꿔야 했던 것 하나 — 출력이 어느 창으로 가나

`getWebContents()` 가 **본창 하나만** 돌려주고 IPC 모듈 일곱이 그것을 쓰고 있었다. 세션 출력·
telemetry·remote 를 `getWebContents(sessionId)` 로 바꿔 **그 세션을 가진 창**으로 보낸다.
아라·MCP·RDP 는 창을 뗄 수 없는 것들이라 본창 고정이다. 소유 창이 이미 닫혔으면 본창으로
떨어진다 — 창이 사라지는 순간 도착한 출력을 버리지 않으려는 폴백이다.

### 정한 것

- **세션은 한 창에만 있다.** 두 창에서 같은 세션을 그리면 xterm 인스턴스가 둘이라 스크롤백이
  갈라진다 — 같은 터미널인데 위로 올려 본 내용이 창마다 다르면 하자다.
- **창을 닫으면 묻는다**(2026-08-22 준영님 결정 — 제보 4번). 그 창의 세션을 **이름으로** 보여 주고
  [종료하고 닫기] / [본창으로 보내기] / [취소]. 되돌리기가 세 번째 버튼으로 남아 있는 이유는
  그전 기본값이 그것이었기 때문이다 — 창 닫기는 실수로도 일어나고, 그때 원격 작업이 통째로
  끊기면 되돌릴 방법이 없다.
- **탭을 창 밖에 놓으면 새 창**(제보 4·31). 탭바 위 = 재정렬, 터미널 영역 = 분할, **창 밖 = 떼어내기**.
  판정은 드래그 끝의 dropEffect('none' = 아무도 안 받음) + 커서의 화면 좌표 둘을 함께 본다.
- **떼어낸 창은 "작업 창"**(준영님 확정): 탭바·분할·하단바·상태바. 연결 트리·아라·설정은 없다 —
  설정 드로어가 두 창에 동시에 뜨는 상태를 만들지 않는 것도 이 선택의 이유다.

### R2 — 창·자리 복원 (2026-08-18)

준영님 확정: "창과 자리까지 복원". 재시작하면 떼어냈던 창이 **그 자리에** 다시 뜨고 그 세션들이
거기 담긴다.

**스키마를 거의 안 늘렸다.** 어느 세션이 어느 창인지는 `sessions[].winId` 가 이미 들고 있어
(R1 에서 넣었다) 스냅샷에 새로 필요한 것은 **창 자리뿐**이다 — `windows?: {winId, bounds}[]`.
옵셔널이라 구버전 스냅샷에 마이그레이션이 필요 없다(없으면 "떼어낸 창이 없었다"는 뜻).

**자리는 main 이 소유한다.** 렌더러는 자기 창 크기는 알아도 다른 창 것은 모르고, 애초에 신뢰
경계 밖 입력으로 창 좌표를 정하지 않는다(`WorkspaceStore.update()` 가 세 필드만 골라 쓰는 것과
같은 원칙). `workspace:save` 가 올 때마다 main 이 지금 떠 있는 창을 그대로 찍는다.

**순서가 이 라운드의 전부다.** 복원은 세션을 새로 만들므로(pty 는 재시작을 못 넘는다) id 가 전부
바뀐다. 그래서 ① 본창이 세션을 다 되살리고 ② 스냅샷의 `winId` 를 **새 id 에 다시 붙인 뒤**
③ 그다음 창을 연다. 뒤집으면 창이 먼저 떠서 자기 세션을 못 찾고 빈 채로 남는다 — 그래서
`win:restore` 한 호출로 묶었다(assign + windows 를 함께 받는다).

| ID | 판단 | 왜 | 자동화 |
|----|------|-----|--------|
| WIN-B1 | 저장된 자리가 화면 안이면 그대로 | — | ✅ 단위 |
| WIN-B2★ | **그 모니터가 없어졌으면 버린다** | 듀얼에서 떼어 놓고 노트북만 들고 나가면 그 좌표가 화면 밖이다 — 창은 열리지만 **찾을 수도 끌어올 수도 없다**(사용자에겐 "창이 안 뜬다"). 준영님이 회사(윈도우)·집(맥북)을 오가시므로 가정이 아니라 일상 경로 | ✅ 단위 |
| WIN-B3 | 음수 좌표도 살린다 | 주 모니터가 원점이 아닐 수 있다(왼쪽·위에 붙인 배치) | ✅ 단위 |
| WIN-R1 | 세션이 하나도 안 붙은 창은 **안 연다** | 저장된 창인데 그 안의 세션이 전부 복원 실패했을 수 있다(SSH 재접속 실패). 빈 창을 띄우고 "닫으세요" 하느니 안 띄운다 | — |

**검증 한계 — 정직하게.** 창 복원은 **앱을 재시작해야** 확인되고 그건 e2e 영역인데, 이번 라운드는
준영님 요청으로 e2e 를 돌리지 않았다(전체 11분). 자리 판정(WIN-B1~B3)은 순수 함수로 떼어 단위
5건으로 잡았고, 스키마 변경이 기존 F6 복원을 깨지 않는 것은 **스모크 265/0** 이 봤다.
**"재시작하면 그 창이 그 자리에 뜬다"는 아직 기계가 확인하지 않았다** — 준영님 확인(A-62) 또는
다음 라운드의 e2e 대상이다.

### 39.1 계획 먼저 (#136, 2026-08-25 준영님 결정)

**문지기(#135)는 만들었다가 걷어냈다.** `Write` 를 막았더니 모델이 `Bash` 로 `printf … > file` 을
돌려 파일을 만들었다(실측, 설계 §3.4f) — 셸이 열린 판에서 파일 차단은 차단이 아니고, 셸까지 막으면
아라가 로컬에서 할 수 있는 일이 거의 없다. 쓸 만한 중간 등급이 없어서 **권한은 사용자의 `~/.claude`
설정을 그대로 따른다**(0.1.0 까지와 같다). 위험한 표면인 아라 자신의 도구는 F23 승인 게이트가 지킨다.

대신 값이 있는 것을 붙였다: **사전 차단이 아니라 사전 합의.** 실측으로 왕복이 성립한다(§3.4g) —
`--permission-mode plan` 은 실제 편집을 막고, 승인 뒤 `set_permission_mode → acceptEdits` 로
**재기동 없이** 같은 대화에서 실행된다. `default` 로 바꾸면 *"권한을 아직 허용하지 않았다"* 로 또
막힌다. 목표 모드를 잘못 고르면 "승인했는데 아무 일도 안 일어난다"가 된다.
