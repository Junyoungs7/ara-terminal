# 계획 — 제품명을 `ARA` 로 (#199)

준영님(2026-09-15):
> *"우리 아라 이름이 A.R.A 로 되어 있어서 사람들이 윈도우에서 검색으로 찾기가 어렵다고 해.
> 그래서 그냥 ARA 로 변경도 해야 해."*

---

## 🔴 이름은 두 줄이다. **본체는 사용자 데이터 이전이다.**

```
productName: A.R.A            ← package.json:3 · electron-builder.yml:2
  ↓ 여기서 파생된다
userData    %APPDATA%\A.R.A                    ← 프로필 · 호스트키 · 설정 · 세션 레이아웃 · 로그
설치 위치    %LOCALAPPDATA%\Programs\A.R.A
```

`src/main` 어디에도 `app.setPath('userData', …)` 가 **없다**(확인함) — Electron 이 `productName` 으로
정한다. **이름만 바꾸면 앱이 `%APPDATA%\ARA` 를 보고, 거긴 비어 있다:**

> **프로필·저장한 호스트키·설정·탭 레이아웃이 전부 사라진 것처럼 보인다.**

지금 쓰시는 분들이 있다. **이전 없이는 못 낸다.**

---

## 무엇이 이름에 매여 있나 — 전수

| | 값 | 바뀌면 |
|---|---|---|
| `package.json` `productName` | `A.R.A` | userData · 설치 경로 · 실행 파일명 · 바로가기 이름 |
| `package.json` `name` | `ara` | 안 바꾼다(npm 패키지명) |
| `electron-builder.yml` `productName` | `A.R.A` | 설치본 파일명 `A.R.A Setup x.y.z.exe` |
| `electron-builder.yml` `appId` | `com.verygood.ara` | 🔴 **안 바꾼다** — 이게 "같은 앱"의 신원이고, 바꾸면 업데이트가 **새 앱 설치**가 된다 |
| `latest.yml` 의 `url`/`path` | `A.R.A Setup …exe` | 파일명이 바뀐다 → **자동 업데이트 경로가 갈린다**(아래 ⚠️) |
| `i18n` `app.name` | 화면 문구 | 상태바·[정보]·설명서 |
| 사이트 · README · 설명서 | `A.R.A` 표기 | 문구만 |

---

## 순서 — 이 순서를 지켜야 데이터가 안 날아간다

### 1단계 · **경로를 이름에서 떼어 낸다** (이름은 아직 안 바꾼다)

`app.whenReady()` **전에** 한 줄:
```ts
app.setPath('userData', join(app.getPath('appData'), 'A.R.A'))
```
⚠️ **`whenReady` 뒤에 부르면 늦다** — 그 전에 이미 여러 경로가 굳는다.
⚠️ 이 판을 **먼저 배포한다.** 이름은 그대로라 사용자에겐 아무 일도 안 일어나고, 다음 판에서
   이름을 바꿔도 앱은 **여전히 옛 폴더를 본다.** 데이터가 안 움직이니 이전 사고가 원천적으로 없다.

**왜 옮기지 않고 고정하나:** 폴더를 복사하는 이전은 실패할 자리가 많다(권한·오피스키퍼 잠금·
중간에 꺼짐·부분 복사). **안 옮기는 것이 가장 안전한 이전이다.** 대가는 폴더 이름이 옛날 것으로
남는 것뿐이고, 그건 사용자 눈에 안 보인다.
⚠️ 새 PC 에 처음 까는 사람은 `%APPDATA%\A.R.A` 가 **새로** 만들어진다 — 이상해 보이지만 그게
   맞다(한 이름으로 통일되어야 다음 판에서 또 갈리지 않는다). 주석에 이유를 박는다.

### 2단계 · 이름을 바꾼다

`productName` 두 곳 → `ARA`. `appId` 는 그대로.

⚠️ **설치 위치가 바뀐다**(`Programs\A.R.A` → `Programs\ARA`). NSIS 는 `appId` 로 기존 설치를 찾아
**업그레이드로 처리하고 옛 폴더를 정리한다** — 다만 이건 **실기로 확인해야 한다.**
🔴 **확인 절차**(배포 전 필수): 1.0.9 가 깔린 PC 에서 새 판으로 업데이트 → ① 프로그램 목록에
   **항목이 하나인가**(둘이면 옛것이 남은 것) ② 시작 메뉴·바탕화면 바로가기가 `ARA` 하나인가
   ③ **프로필이 그대로 있는가** ④ `%APPDATA%\A.R.A` 를 계속 쓰는가.

### 3단계 · 자동 업데이트가 이름을 넘어가나 — 🔴 여기가 제일 위험하다

설치본 파일명이 `A.R.A Setup x.exe` → `ARA Setup x.exe` 로 바뀐다. `latest.yml` 은 새 판을 가리키니
**받는 것은 된다.** 문제는 **차등 다운로드**다 — 직전 판의 캐시(`ara-updater/installer.exe`)와
파일명이 달라지므로 그 판만 **통짜로 받을 가능성**이 있다. 기능이 깨지는 것은 아니고 한 번 느리다.

⚠️ **그리고 이름 바꾸는 판은 "업데이트로 넘어가는 것"을 반드시 실기로 본다.** 여기서 끊기면
사용자는 **옛 앱에 갇힌다**(새 판을 손으로 받아야 한다). 배포 전에 옛 판 깐 PC 로 한 번 넘어가 본다.
→ 이 검증을 `docs/release-test.md` 에 **단계로 추가한다**(한 번 쓰고 버릴 절차가 아니다).

### 4단계 · 문구·자산

`i18n` 의 `app.name` · 사이트(`index.html`·`manual.html`·`changelog.html`) · `README.md` ·
`docs/**` 의 `A.R.A` 표기. ⚠️ **기계적 치환 금지** — 지난 판 패치 내역과 과거 주석의 `A.R.A` 는
그때의 사실이라 그대로 둔다. 바꿀 것은 **지금 화면에 나가는 문구**뿐이다.

---

## 안 하는 것

- **`appId` 변경** — 바꾸면 업데이트가 아니라 **새 앱**이 된다. 옛 앱이 남고 데이터가 갈린다.
- **`%APPDATA%\A.R.A` → `ARA` 폴더 이전** — 위 1단계 참고. 얻는 것이 폴더 이름뿐이고 잃을 수
  있는 것이 사용자 데이터 전부다.
- **`package.json` `name`** — npm 패키지명이라 화면에 안 나온다.

---

## 시험

- 순수로 뗄 것이 거의 없다 — **이 항목은 실기 검증이 전부다.** 게이트가 잡아 줄 수 없다.
- ⚠️ 그래서 **배포 전 확인 목록을 먼저 쓰고** 그다음 코드를 만진다(순서를 뒤집지 않는다).
- 자동 시험으로 할 수 있는 최소: `productName` 과 `setPath` 인자가 **서로 달라야 한다**는 단언
  (이름을 바꿀 때 경로까지 같이 바꾸는 사고를 막는다 — 이 계획 전체가 막으려는 그 사고다).
