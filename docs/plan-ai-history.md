# ① 셸 히스토리 — AI CLI 세션을 어떻게 할까

지금은 AI CLI 세션이 `type: 'local'` 이라 scope 가 `'local'` 이다. 그래서
**Claude·Codex 에 친 문장이 전부 `history.json` 에 쌓인다**(실측: 한글 15자 초과 22건).
셸 제안 목록도 그만큼 더러워진다 — *"우선 1~7을 먼저 작업해줘"* 가 `cd` 옆에 뜬다.

| | 안 | 잃는 것 | 크기 |
|---|---|---|---|
| **(가)** | AI 세션은 **scope 를 안 준다**(안 쌓는다) | AI 프롬프트 자동완성 | S |
| **(나)** | 별도 scope `ai:<cli>` — 디스크에 남김 | 없음 | S |
| **(다) ✅** | 별도 scope + **메모리만**(디스크 저장 안 함) | 앱을 끄면 그 제안이 사라짐 | S |

**권고 (다).** AI 탭에서도 *"계속"·"테스트 돌려줘"·"커밋해줘"* 는 반복해서 친다 — 제안이 값이 있다.
그런데 그 문장이 **디스크에 영구히 남을 이유는 없다.** (가)보다 한 줄 더 들고 둘 다 얻는다.
⚠️ `loadHistory`/`appendHistory` 에 "메모리 전용 scope" 집합을 두면 된다(`history.ts`).

# ② AI 대화 — *"도구 이름만"* 은 **과교정이다**

## 지금 사실부터 (`src/main/ai/apiChatLog.ts`)

**도구 호출을 아예 안 남긴다.** `{type: 'user'|'assistant', message:{content}, at}` 뿐이다.
→ 준영님 걱정(*"도구 쓸 때 비밀번호가 쌓인다"*)은 **아직 사실이 아니다.**
→ 대신 다른 값을 잃고 있다: **이어서 열면 모델이 자기가 뭘 했는지 모른다**(같은 걸 또 한다).

## 이름만 적으면 안 되는 이유 둘

1. 🔴 **대화를 이어갈 수 없다.** API 규약상 `tool_use` 에는 `input` 이, `tool_result` 에는
   `content` 가 **필수**다. 이름만 남기면 복원한 대화가 문법적으로 성립하지 않는다.
2. 🔴 **감사 가치가 0 이 된다.** *"`server_run` 3회"* 로는 아무것도 알 수 없다.
   *"`ps.kill{pid:4821}`"* 여야 사고를 추적한다. "아라를 통해서만"을 요구한 그 감사와 같은 이야기다.

## 🔴 그리고 — 위험한 인자는 **사실상 하나뿐이다**

도구 표를 훑으면 대부분 비밀이 못 들어간다:

| 도구 | 인자 | 비밀 |
|---|---|---|
| `server_run` | `cmdId`(표의 id) + 검증된 `args`(pid·유닛명·포트) | ❌ |
| `ssh_connect` | `profileId` | ❌ **vault 는 main 이 연다** — 이 설계가 이미 답이다 |
| `sftp_*` · `log_read` | 경로 | ❌ |
| **`session_input`** | **`data: z.string()` — PTY 에 쓰는 임의 문자열** | 🔴 **여기가 전부다** |

19개를 가리려고 이름만 남기는 것은, 1개 때문에 나머지를 버리는 일이다.

## ✅ 대신: **도구마다 무엇을 남길지 표에 적는다**

```ts
type Redact = 'full' | 'shape' | 'none'
//  full  — 인자를 그대로 (대부분)
//  shape — 키는 남기고 값은 길이만  { data: '…(37자)' }
//  none  — 이름만
```

🔴 **타입으로 강제한다** — 새 도구를 만들면서 이 값을 **안 적을 수가 없게**. 이 저장소가 이미
쓰는 방식이다(`COMMANDS` 의 `write` 플래그 · paseo 의 `operation-permissions.ts`
*"새 RPC 에 권한을 안 적을 수가 없게"*). 스캐너보다 낫다는 것을 #201 에서 증명했다.

## ✅ 그리고: **메모리(컨텍스트)와 디스크(기록)를 가른다**

| | 무엇이 들어가나 | 왜 |
|---|---|---|
| **메모리** (진행 중 대화) | **전문** | API 가 요구한다. 세션이 끝나면 사라진다 |
| **디스크** (`*.jsonl`) | `redact` 적용본 | 남는 것이라 가린다 |

⚠️ **대가를 정직하게**: 디스크본으로 이어 열면 모델이 가려진 자리를 **모른다**.
`session_input` 이 `…(37자)` 면 "아까 뭘 쳤는지" 모른 채 이어간다.
**받아들일 만하다** — 비밀번호를 기억하는 AI 보다 낫다. 문구로도 알린다.

## `session_input` 은 어떻게 — 규칙을 두 벌 만들지 않는다

늘 `shape` 로 두면 *"아라가 서버에 무엇을 쳤나"* 를 영영 못 본다(감사의 핵심인데).
→ **`full` 이되, 그 세션의 커서 줄이 비밀번호 프롬프트면 `shape`.**
①의 `isPasswordPrompt` 를 **그대로 쓴다**(`renderer/store/history.ts` → `shared/` 로 옮긴다).
main 은 `sessions.peek(id)` 로 꼬리를 볼 수 있으니 판정할 자리가 있다.
⚠️ 한 규칙을 두 곳이 쓰는 것이지, 두 규칙을 만드는 것이 아니다.

## 🔴 더 큰 이야기 — 가리기는 **두 번째** 방어선이다

API 로 가면 대화 전문이 **어차피 Anthropic 으로 나간다.** 디스크를 가려도 전송은 된다.
그러니 *"비밀번호가 안 쌓이게"* 의 본체는 **AI 에게 비밀을 주지 않는 설계**이고,
**아라는 이미 그렇게 되어 있다**:

- `ssh_connect` 는 `profileId` 만 받고 **vault 는 main 이 연다**
- sudo 비밀번호도 main 이 꺼내 `sudo -S` 의 **stdin 으로** 넣는다(명령줄에 안 싣는다 —
  `remoteCatalog.ts:224` 주석: *"명령줄에 실었다면 원격의 ps 목록과 감사 로그에 그대로 찍힌다"*)
- `getSudoPw` 는 키 인증 프로필이면 `null` 을 준다(패스프레이즈 유출 차단, AUDIT-R1)

🔴 **API 전환에서 이 원칙을 유지하는 것이 진짜 답이다.** `redact` 는 사람이 실수로
채팅창에 비밀번호를 붙여넣는 경우를 위한 두 번째 그물이다.

따로 하면 기록만 먼저 생기고 가리개가 늦는다.
