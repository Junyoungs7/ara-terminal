## 1. 🔴 첫 번째 갈림길 — 신고를 **받을 서버**가 없다

다운로드 사이트는 `caddy file-server --root /srv` **읽기 전용 마운트**다(`deploy-site.mjs:97`).
정적 파일만 준다 — 신고를 저장할 곳이 없다. 무언가 **쓰기를 받는 것**이 하나 있어야 한다.

| | 안 | 좋은 점 | 대가 |
|---|---|---|---|
| **(가) 자체 작은 서버** ✅ | Node 서버 하나를 **별도 컨테이너**로(`ara-reports`), 8000~9000 중 한 포트. 저장은 볼륨의 파일 | 준영님 그림 그대로 · 사이트와 한 몸 · 우리가 모양을 정한다 | 서버 하나를 우리가 운영한다(작다 — 수백 줄) |
| (나) 사내 GitLab 이슈 | 아라가 GitLab API 로 이슈를 연다 | 코멘트·상태·첨부가 **이미 다 있다** | 신고자마다 GitLab 계정 필요 · 토큰을 앱에 심어야 함(누구나 꺼낸다) · "다운로드 사이트에 메뉴" 가 아니게 됨 |

**권고 (가).** 🔴 **`ara-site` 에 얹지 않는다** — 프록시 때와 같은 이유다: 그 컨테이너가
자동 업데이트 채널이고(Range 요청 → 차등 다운로드), 신고 서버가 죽거나 꽉 차도 업데이트는 살아야 한다.
그리고 지금 배포는 **무상태**(매번 컨테이너를 지우고 다시 만든다 — `deploy-site.mjs:92`)라,
거기 얹으면 **배포할 때마다 신고가 날아간다.**

## 2. 자동으로 뽑을 것 — 그리고 **안 뽑을 것**

| 항목 | 기본 | 출처 | 비고 |
|---|---|---|---|
| 앱 버전 · OS · Electron · GPU 렌더러 | ✅ 켬 | `app.getVersion` · `termRenderer`(이미 [정보]에 뜬다) | 재현의 절반이 이것이다 |
| **창 캡처** | ✅ 켬 · **미리보기 필수** | `webContents.capturePage()` — **아라 창만**(전체 화면 아님) | 🔴 §3 |
| main 오류 로그 **꼬리 200줄** | ✅ 켬 | `main-error.log` | `maskSecrets` 적용 후 |
| **렌더러 오류** 최근 50건 | ✅ 켬 | 🔴 **지금 수집하는 곳이 없다** — `window.onerror`·`unhandledrejection` 링버퍼를 새로 단다 | 화면 쪽 결함은 지금 아무 기록도 안 남는다 |
| 세션 **모양** | ✅ 켬 | 종류별 개수(`ssh 2 · local 1 · rdp 0`) · 떼어낸 창 수 · 활성 세션 종류 | 호스트 이름·경로는 **안 넣는다** |
| 설정 | ✅ 켬 | 폰트·배율·렌더러 등 `ui` prefs | 비밀 없음 |
| 터미널 화면 텍스트 | ⬜ **끔** | 활성 세션의 보이는 줄 | 🔴 비밀·고객 정보가 흔히 있다. 사람이 켜야만 |
| 셸 히스토리 · AI 대화 · 프로필 · 호스트키 | ❌ **절대 안 넣음** | — | #204 에서 막은 것을 여기서 다시 열지 않는다 |

## 3. 🔴 캡처는 위험하다 — 보여 주고, 뺄 수 있게

아라 화면은 대개 **터미널**이다. 거기엔 비밀번호 프롬프트 직후 화면, DB 조회 결과(고객 개인정보),
`.env` 를 `cat` 한 결과가 떠 있을 수 있다. 이미지는 `maskSecrets` 로 가릴 수도 없다.

- **보내기 전에 캡처를 그대로 보여 준다.** 사람이 보고 보낸다
- **체크 하나로 뺀다**(기본은 켬 — 신고의 가치 절반이 그림이다)
- ⚠️ 문구로 알린다: *"사내 개발자 모두가 볼 수 있습니다. 화면에 비밀번호·고객 정보가 있으면 빼 주세요"*
- 🔴 **타이밍**: 메뉴를 누르는 순간 **먼저 찍고** 그다음 신고 창을 띄운다.
  신고 창이 뜬 뒤에 찍으면 신고 창이 찍힌다

(나중에) 캡처 위에 사각형으로 가리기 — P2. 지금은 "빼기"로 충분하다.

## 4. ⚠️ 사내 DLP(오피스키퍼) — 첨부가 막히거나 **바뀔 수 있다**

회사 PC 는 파일 업로드를 막거나 *"오피스키퍼 ~ 파일이다"* 로 **바꿔 치기**할 수 있다.
캡처·로그가 그 대상이 될 수 있다.

- 서버가 받은 첨부의 **sha256 을 돌려주고**, 아라가 보낸 것과 대조한다
- 다르면 신고는 **그대로 접수**하되 *"사내 보안 프로그램이 첨부를 바꿨을 수 있습니다"* 를 신고에 표시한다
- 🔴 **자동 재시도하지 않는다**(준영님 규칙 — 막히면 계속 시도하지 말고 알린다)
- ⚠️ 첫 실기 시험에서 막히면 **준영님께 보고**하고 멈춘다

## 5. 누가 신고했나 — 답을 돌려주려면 알아야 한다

| | 안 | 대가 |
|---|---|---|
| (a) 이름 입력(선택) | 신고 창에 이름 칸 | 안 적으면 답할 사람을 모른다 |
| (b) OS 계정 자동 | `os.userInfo().username`(예: 사번) | 🔴 개인을 식별하는 값이다 — 사내 서버라도 **모두가 보는 목록**에 뜬다 |
| (c) 익명 기기 ID | 설치마다 난수 하나 | 사람은 모르지만 "내 신고" 는 찾을 수 있다 |

**권고 (a)+(c)**: 이름은 적고 싶은 사람만, 기기 ID 는 늘(화면엔 안 보임) — 그러면
나중에 아라 안에서 **"내 신고" 상태**를 보여 줄 수 있다(P2).

## 6. 상태와 처리 흐름 — "PR 처럼"

```
접수 ─→ 확인 중 ─→ 고침(1.0.13) ─→ 닫힘
   └─→ 재현 안 됨 / 의도된 동작 / 중복(#0003)
```

- **코멘트 타래** — 준영님과 신고자가 주고받는다(신고자는 기기 ID 로 자기 신고에만)
- **고친 판**을 지정하면 상세에 *"1.0.13 에서 고쳤습니다 →"* 가 **패치 내역의 그 판 링크**로 뜬다
  (`changelog.html#v1-0-13` — 이미 판마다 id 가 있다)
- 🔴 반대 방향도 건다: **패치 내역 항목에 `(#0012)`** 을 적으면 그 신고로 링크 — 둘이 서로를 가리킨다
- 하루 한 번 확인 — 사이트 목록에 **"접수" 상태만 보기** 필터 하나면 된다

### 관리 권한
상태·코멘트·고친 판을 바꾸는 것은 **준영님만**. 서버 환경변수의 관리 비밀번호로 한다.
🔴 그 비밀번호는 **대화에 적지 않는다**(배포 비밀번호 사고의 교훈) — 서버에서 직접 설정한다.

### 확정이 낳는 것 하나 — 신고자는 **자기 캡처를 아라 안에서** 본다

"신고자만 본다"를 서버가 가리려면 요청에 **기기 ID** 가 실려야 한다. 크롬으로 사이트를 열면
그 값이 없다 → 사이트(크롬)에서는 **준영님(관리 비밀번호)만** 캡처·로그를 본다.
신고자가 자기 첨부를 다시 보는 길은 아라 안 **"내 신고"** 인데 그건 P2 다.
1.0.13 에서 신고자는 **보내기 전 미리보기**로 이미 봤으므로 잃는 것이 거의 없다.
⚠️ 기기 ID 는 사실상 **열쇠**다 — 화면·로그·신고 본문 어디에도 찍지 않는다.
